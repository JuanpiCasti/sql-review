Data types, and the shape of nothing

Numbers that lie, timestamps that drift across time zones, text that pretends to be three different types, and a value that compares equal to neither itself nor its absence.

Before any of the harder Postgres mechanics make sense, the type system has to be in your head. Most of the trouble engineers hit in real codebases — silent rounding, surprise time-zone shifts, queries that return nothing because a single column was NULL — comes from misunderstanding what a column actually contains. This chapter is the ground-floor reference.

Data types, in one card

numeric
Exact arbitrary-precision. Use for money.
float8
IEEE 754 double. Fast, lossy. Never for money.
text
The right default. varchar(n) only when an external system imposes the limit.
timestamptz
UTC instant. The right default for "when did this happen."
timestamp
Wall-clock with no zone. Almost always wrong.
NULL
"Unknown." NULL = NULL is NULL, not true.
IS DISTINCT FROM
The equality you actually wanted across nullable columns.
Arrays
int[], text[]. GIN-indexable. Don't model relations with them.
Ranges
tstzrange, int4range. Pair with EXCLUDE for non-overlap constraints.
