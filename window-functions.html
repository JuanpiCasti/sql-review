Window functions, or, aggregation without collapse

Compute per-row values that depend on other rows — running totals, ranks, lags, moving averages — without losing the rows themselves. The single most powerful clause in SQL.

A window function is an aggregate that returns one value per input row instead of one value per group. It runs over a window — a partitioned, ordered slice of the result set — and each row sees the aggregate computed over its own slice. Where GROUP BY collapses rows, OVER preserves them. Once you internalise this difference, half of "this needs a subquery" turns out to need only a single OVER clause.

Sample data sales(salesperson, region, sold_at, revenue), a handful of rows per region. Every example below references it.

§ 6.1 Anatomy of the OVER clause

The shape:

function(args) OVER (
  PARTITION BY  partition_expr [, ...]    -- split rows into independent groups
  ORDER BY      order_expr     [, ...]    -- order within each partition
  frame_clause                            -- which neighbouring rows count
)

All three pieces are optional. Omit PARTITION BY and the whole result is one partition. Omit ORDER BY and the rows have no defined order inside the partition. Omit the frame and Postgres uses a default frame that depends on whether ORDER BY is present (the source of the famous LAST_VALUE trap — § 6.5).

Ex. 6.1 Running total per region

SELECT region,
       sold_at,
       revenue,
       sum(revenue) OVER (PARTITION BY region ORDER BY sold_at)
         AS running_total
FROM   sales
ORDER  BY region, sold_at;

Result

Each region's running total restarts at the partition boundary; within a region, the sum accumulates in sold_at order. No GROUP BY, no self-join.

§ 6.2 The ranking family

Three almost-identical functions that differ only in how they treat ties:

ROW_NUMBER()
Always 1, 2, 3, … even on ties. Ties broken arbitrarily by the database.
RANK()
Tied rows share a rank; the next rank skips the count of ties. 1, 2, 2, 4.
DENSE_RANK()
Tied rows share a rank; the next rank does not skip. 1, 2, 2, 3.

Ex. 6.2 Ranking salespeople within each region by revenue

SELECT region,
       salesperson,
       revenue,
       row_number() OVER w AS rn,
       rank()       OVER w AS rnk,
       dense_rank() OVER w AS drnk
FROM   sales
WINDOW w AS (PARTITION BY region ORDER BY revenue DESC)
ORDER  BY region, revenue DESC;

Result — note the tied 200s

regionsalespersonrevenuernrnkdrnk
EUAda 300111
EUBeni 200222
EUCleo 200322
EUDario 150443

The choice:

  • ROW_NUMBER for "give me the top 1 / top N per group" when you don't care which of equally-good rows you get.
  • RANK for Olympic-style scoring — two silver medallists, no bronze.
  • DENSE_RANK when you want to count distinct ranks. After "1, 2, 2, 3" the highest rank equals the number of distinct values.

Two more in the family, less common:

PERCENT_RANK()
(rank - 1) / (total - 1). Maps the partition to [0, 1].
NTILE(n)
Bucket the partition into n roughly-equal groups, numbered 1..n. Quartiles, deciles, percentile buckets.
CUME_DIST()
Cumulative distribution: rows ≤ current / total.

§ 6.3 Top-N per group via window functions

Ex. 6.3 Top 2 salespeople per region

SELECT *
FROM (
  SELECT region, salesperson, revenue,
         row_number() OVER (PARTITION BY region ORDER BY revenue DESC) AS rn
  FROM sales
) t
WHERE rn <= 2;

Why the subquery? Window functions are computed after WHERE and GROUP BY but before the outer SELECT's list. You can't filter on rn in the same query that defines it — you need an outer scope. (Compare with the LATERAL spelling in Ch. IV § 4.7: for small N and many groups, LATERAL with LIMIT usually wins; for moderate N or a small number of groups, the window-function form is fine.)

§ 6.4 LAG and LEAD

lag(x, offset, default) returns x from the row offset positions before the current row; lead looks forward. Both are invaluable for differences, gaps, and state-change detection.

Ex. 6.4 Daily delta in stock price

SELECT ticker,
       day,
       price,
       price - lag(price) OVER w AS d_price,
       100 * (price - lag(price) OVER w) / lag(price) OVER w AS pct_change
FROM   prices
WINDOW w AS (PARTITION BY ticker ORDER BY day)
ORDER  BY ticker, day;

The first row of each partition has no preceding row; lag returns NULL there unless you pass a default: lag(price, 1, price) OVER w would return the current price for the first row, making the delta zero.

§ 6.5 The frame clause

Inside each partition, the frame defines which rows the aggregate sees for the current row. This is where window functions get powerful — and where they confuse people most.

The full syntax has three parts:

{ROWS | RANGE | GROUPS} BETWEEN frame_start AND frame_end
  [EXCLUDE {CURRENT ROW | GROUP | TIES | NO OTHERS}]

Where each endpoint is one of:

UNBOUNDED PRECEDING
The first row of the partition.
n PRECEDING
n rows / units before current.
CURRENT ROW
The current row (interpretation depends on mode).
n FOLLOWING
n rows / units after current.
UNBOUNDED FOLLOWING
The last row of the partition.

And the three modes:

ROWS
Physical row count. n PRECEDING means literally n rows back.
RANGE
Logical offset on the ORDER BY value. n PRECEDING means all rows whose value is within n of the current row's value.
GROUPS
Peer-group offset. n PRECEDING means n distinct ORDER BY values back.

Ex. 6.5 Seven-day moving average

SELECT day,
       sales,
       avg(sales) OVER (
         ORDER BY day
         RANGE BETWEEN interval '6 days' PRECEDING AND CURRENT ROW
       ) AS ma7
FROM   daily_sales;

Use RANGE with an interval when there might be gaps in the dates — the average is over the past seven calendar days, not the past seven recorded rows.

The LAST_VALUE trap

The default frame when ORDER BY is present is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW — not the full partition. Which means last_value(x) OVER (PARTITION BY g ORDER BY t) returns the value at the current row, not the value at the partition's last row.

To get the actual last value, you must spell out the frame:

last_value(x) OVER (
  PARTITION BY g
  ORDER BY t
  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
)

Or use max(x) if the last is also the max, or restructure the query with a subquery and ORDER BY t DESC LIMIT 1.

§ 6.6 Named windows

When several functions share the same window, define it once with WINDOW and refer to it by name. Ex. 6.2 and 8.4 already used this. The full grammar lets later windows extend earlier ones:

Ex. 6.6 Inheriting a window

SELECT region, salesperson, revenue,
       rank()       OVER w1                 AS rnk,
       sum(revenue) OVER w2                 AS running_total
FROM   sales
WINDOW
  w1 AS (PARTITION BY region ORDER BY revenue DESC),
  w2 AS (w1 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW);

w2 reuses w1's PARTITION BY and ORDER BY, adding only a frame.

§ 6.7 first_value, last_value, nth_value

Three positional functions, each returning a value from a specific row within the frame:

first_value(x)
The first row of the frame.
last_value(x)
The last row of the frame. (Remember the trap.)
nth_value(x, n)
The nth row (1-indexed); NULL if the frame is shorter.

Ex. 6.7 Best-revenue salesperson alongside each row, per region

SELECT region, salesperson, revenue,
       first_value(salesperson) OVER (
         PARTITION BY region ORDER BY revenue DESC
       ) AS top_in_region
FROM   sales;

For this use (the maximum value across the partition) first_value with ORDER BY … DESC works correctly with the default frame, because the first row of UNBOUNDED PRECEDING … CURRENT ROW in the first row of the partition is itself.

§ 6.8 Execution model and indexes

A query with window functions executes in this order:

  1. FROM / JOIN produces the row source.
  2. WHERE filters it.
  3. GROUP BY / HAVING aggregate.
  4. Window functions compute per-row over their windows.
  5. SELECT projects.
  6. DISTINCT, ORDER BY, LIMIT.

An index on (partition_cols, order_cols) lets Postgres feed the WindowAgg node already-sorted input and skip the sort. For Ex. 6.1, an index on (region, sold_at) turns the plan from Sort → WindowAgg into IndexScan → WindowAgg.

Window functions, in one card

OVER ()
Aggregate over the entire result set, per-row.
PARTITION BY
Independent windows; the aggregate restarts at each partition.
ROW_NUMBER
1, 2, 3 — always. Ties broken arbitrarily.
RANK
Ties share a rank; next rank skips. 1, 2, 2, 4.
DENSE_RANK
Ties share a rank; next rank doesn't skip. 1, 2, 2, 3.
NTILE(n)
Bucket into n equal-ish groups. Use for quartiles/deciles.
LAG / LEAD
Value from offset rows back / forward. Pass a default for partition edges.
FIRST_VALUE / LAST_VALUE
Positional. LAST_VALUE needs an explicit frame to do what you expect.
Default frame
RANGE UNBOUNDED PRECEDING … CURRENT ROW when ORDER BY present.
WINDOW name AS (…)
Define once, reuse. Later windows can extend earlier ones.
Index strategy
Index on (partition_cols, order_cols) avoids the sort before WindowAgg.
