Aggregates & GROUP BY

Collapsing many rows into one — and then collapsing many groups into many summary rows. The aggregate clause, the FILTER qualifier, and the cube of grouping sets.

An aggregate function reduces a set of rows to a single value: count(*), sum(amount), avg(latency). The GROUP BY clause partitions the input into groups so that the aggregate produces one row per group. Everything else in this chapter — HAVING, FILTER, grouping sets — is built on top of those two ideas.

Sample schema A sales(region, product, sold_at::date, qty, revenue) table with a few hundred rows across three regions, four products, and a year of dates. Examples reference it.

§ 5.1 The shape of a grouped query

The canonical form:

Ex. 5.1 Revenue per region

SELECT region,
       count(*)             AS orders,
       sum(revenue)         AS revenue,
       avg(qty)::numeric(10,2) AS avg_qty
FROM   sales
GROUP  BY region
ORDER  BY revenue DESC;

Result

EU41282,440.003.10
US38174,995.002.88
APAC22748,210.003.42

Three rules govern what may appear in the SELECT list of a grouped query:

  • Columns listed in GROUP BY.
  • Aggregates over any column.
  • Columns functionally dependent on the GROUP BY columns — e.g. you may GROUP BY orders.id and select any column of orders, because the primary key determines them all. Postgres figures this out; most other databases don't.
The classic error

ERROR: column "x" must appear in the GROUP BY clause or be used in an aggregate function. You selected a bare column that's neither in the group key nor under an aggregate. The fix is either to add it to GROUP BY or to wrap it in min() / max() / any_value() when you genuinely don't care which value you get.

§ 5.2 NULL in aggregates and groups

Two rules to memorise:

  • All aggregates except count(*) ignore NULL inputs. sum(x) over {1, NULL, 3} is 4, not NULL. count(x) counts only non-null values; count(*) counts rows regardless.
  • Every NULL in a GROUP BY column falls into the same group. This is the opposite of how NULL behaves in = comparisons (where NULL = NULL is unknown). The GROUP BY rule is the special case.

Ex. 5.2 Counting rows vs. counting values

SELECT count(*)         AS rows,        -- 5
       count(email)     AS with_email,  -- 3 (nulls ignored)
       count(DISTINCT email) AS unique_emails
FROM   users;

§ 5.3 WHERE vs HAVING

The two filters look similar but apply at different stages.

WHERE
Filters input rows before grouping. Cannot reference aggregates.
HAVING
Filters groups after aggregation. Must reference aggregates (or grouped columns).

Ex. 5.3 Regions with more than 300 orders, excluding test data

SELECT region, count(*) AS orders
FROM   sales
WHERE  sold_at >= date '2026-01-01'   -- row filter, cheap
GROUP  BY region
HAVING count(*) > 300;                -- group filter, after the count

Put every condition you possibly can in WHERE rather than HAVING — WHERE runs before the aggregation does work. HAVING count(*) > 300 is unavoidable; HAVING region = 'EU' should have been WHERE.

§ 5.4 The FILTER clause

Conditional aggregation, properly. FILTER (WHERE …) attached to an aggregate restricts that aggregate's input without restricting the surrounding query. It replaces the older CASE WHEN x THEN 1 END idiom and is strictly nicer:

Ex. 5.4 Multiple counters in one pass

SELECT region,
       count(*)                                              AS total,
       count(*) FILTER (WHERE revenue > 1000)                AS high_value,
       count(*) FILTER (WHERE sold_at >= date '2026-06-01')  AS h2,
       sum(revenue) FILTER (WHERE product = 'widget')        AS widget_rev,
       avg(qty)     FILTER (WHERE qty > 0)                   AS avg_qty
FROM   sales
GROUP  BY region;

The query scans the table once and computes five conditional aggregates in parallel. The pre-FILTER equivalent — count(*) FILTER (WHERE x) as count(CASE WHEN x THEN 1 END) — works but is harder to read and gives sum different NULL semantics.

§ 5.5 DISTINCT inside an aggregate

Aggregates accept DISTINCT to deduplicate before they reduce:

Ex. 5.5 Distinct buyers per region

SELECT region,
       count(DISTINCT customer_id) AS unique_customers,
       array_agg(DISTINCT product ORDER BY product) AS products
FROM   sales
GROUP  BY region;

Note the ORDER BY inside the aggregate's parenthesis. It applies to the values being aggregated, not to the overall query — useful for array_agg, string_agg, jsonb_agg when the order matters.

§ 5.6 Useful aggregates beyond the basics

array_agg(x)
Collect values into an array. Pairs with ORDER BY inside the call.
string_agg(x, ', ')
Concatenate into a string with a separator.
jsonb_agg(row_to_json(t))
Build a JSON array of grouped rows.
jsonb_object_agg(k, v)
Build a JSON object from grouped key/value pairs.
bool_and / bool_or
Aggregate boolean conjunctions / disjunctions across rows.
bit_and / bit_or
Bitwise reductions, occasionally useful for flag columns.
every(x)
Standard SQL alias for bool_and.

§ 5.7 Ordered-set aggregates

A few aggregates need the input sorted to make sense — percentiles, modes. They use special syntax: WITHIN GROUP (ORDER BY …).

Ex. 5.6 p50, p95, p99 latency per endpoint

SELECT endpoint,
       percentile_cont(0.50) WITHIN GROUP (ORDER BY latency_ms) AS p50,
       percentile_cont(0.95) WITHIN GROUP (ORDER BY latency_ms) AS p95,
       percentile_cont(0.99) WITHIN GROUP (ORDER BY latency_ms) AS p99,
       mode() WITHIN GROUP (ORDER BY status_code)               AS modal_status
FROM   requests
GROUP  BY endpoint;

percentile_cont interpolates between adjacent values (continuous); percentile_disc picks the row whose cumulative weight first crosses the percentile (discrete). Use _cont for numeric metrics, _disc for categorical ones where interpolation makes no sense.

§ 5.8 GROUPING SETS, ROLLUP, CUBE

Sometimes you want subtotals — revenue by (region, product), by region alone, by product alone, and overall, all in one result. The naïve approach is four queries joined by UNION ALL. GROUPING SETS does it in one pass:

Ex. 5.7 A pivot summary in one query

SELECT region,
       product,
       sum(revenue) AS revenue
FROM   sales
GROUP  BY GROUPING SETS (
  (region, product),   -- the cells
  (region),            -- region subtotals
  (product),           -- product subtotals
  ()                   -- grand total
);

Result (excerpt)

Subtotal rows have NULL in the columns they aggregated over. Genuine NULL values look the same — so use the GROUPING() function to disambiguate:

Ex. 5.8 The GROUPING() bitmask

SELECT GROUPING(region, product) AS g,        -- 0..3 bitmask
       coalesce(region, 'ALL REGIONS')   AS region,
       coalesce(product, 'ALL PRODUCTS') AS product,
       sum(revenue)
FROM   sales
GROUP  BY GROUPING SETS ((region, product), (region), ());

Two shorthands sit on top of GROUPING SETS:

ROLLUP (a, b, c)
Expands to (a,b,c), (a,b), (a), () — hierarchical subtotals.
CUBE (a, b, c)
Every subset of the columns — 2ⁿ grouping sets. Use sparingly; the cardinality grows fast.

§ 5.9 GROUP BY ALL (Postgres 16+)

A small but welcome addition: GROUP BY ALL tells Postgres to group by every non-aggregate column in the SELECT list. It saves repetition in big reporting queries:

Ex. 5.9 Less typing, same result

SELECT region, product, date_trunc('month', sold_at) AS month,
       sum(revenue), count(*)
FROM   sales
GROUP  BY ALL;
-- equivalent to: GROUP BY 1, 2, 3

Aggregation, in one card

count(*)
Counts rows including nulls. Every other aggregate ignores nulls.
WHERE vs HAVING
WHERE before aggregation, HAVING after. Push conditions to WHERE whenever possible.
FILTER (WHERE …)
Conditional aggregation per-column, in one pass. Replaces CASE WHEN.
agg(DISTINCT x)
Deduplicate before aggregating; can take ORDER BY inside the call.
array_agg / string_agg / jsonb_agg
Collect-into-array / string / JSON aggregates.
WITHIN GROUP (ORDER BY)
Ordered-set aggregates: percentile_cont, percentile_disc, mode.
GROUPING SETS
Multiple groupings in one pass. Subtotals appear with NULLs in the rolled-up columns.
ROLLUP / CUBE
Shorthands for hierarchical / full-power subtotals.
GROUPING(col,...)
Bitmask distinguishing real NULLs from subtotal NULLs.
GROUP BY ALL
PG 16+. Groups by every non-aggregate selected column.
